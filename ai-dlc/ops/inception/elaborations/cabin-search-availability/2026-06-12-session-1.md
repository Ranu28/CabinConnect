## Discussion Notes

The six unit files were found pre-existing in `build/units/` with status `Ready`, referencing a session doc and intent file that did not exist. This session adopted them as the baseline rather than regenerating, then audited each against the intent's Decisions table. Gap analysis findings:

1. Pagination — intent decided day-one pagination; CSA-002 said "no pagination in first version" and CSA-005 had no paging behaviour.
2. Holds — CSA-002 excluded Confirmed/Pending Bookings but not active Holds; the decided cleanup job had no unit.
3. Published-only filter was implicit, not an explicit AC on CSA-002.
4. The intent's performance target (<1s at 10,000 published cabins) was not captured in any unit.
5. Host search preview had no unit.

### Key Decisions
| Decision | Reasoning |
|---|---|
| Adopt CSA-001–006 as baseline; revise rather than regenerate | Units were well-formed and consistent with the glossary and edge cases; regeneration would discard valid work |
| Defer all Hold handling (query exclusion + expiry cleanup job) to the future Booking intent | Holds are only created by the booking flow, which is out of scope here; building the filter and job now would model and test an entity nothing creates. CSA-002 carries an explicit note that its availability query must be extended when Holds land |
| Offset pagination (`page` / `pageSize`, `totalCount` in response) | Simple to implement and consume; adequate at the launch catalogue size (low thousands). Cursor paging revisited only if concurrent-change artefacts become a real problem |
| Host preview = the public search itself | Decision "published cabins only" means the public endpoint already shows the Host exactly what Guests see; no dedicated preview unit needed |
| Result cards show grouped rate lines + prominent Total; per-night breakdown belongs to the cabin detail page | Reconciles the intent's pricing decision with CSA-004's existing ACs — grouped lines (e.g. "2 nights Base + 3 nights Seasonal") are a summary, not the per-night breakdown |
| Performance target recorded as a non-functional AC on CSA-002 | "<1s at 10k published cabins" is testable and belongs with the query unit |

### Deferred / Out of Scope
| Item | Why Deferred |
|---|---|
| Hold exclusion in availability query | Hold entity arrives with the Booking intent; CSA-002 notes the required extension |
| Hold expiry background cleanup job | Same — unit to be created under the Booking intent |
| Cabin detail page (per-night price breakdown) | Separate intent; cards show grouped lines only |
| Dedicated Host preview tooling | Public search already serves this need |
